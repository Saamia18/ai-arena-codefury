# 🧬 AI Arena

**Find the AI that backs your ambition.**

AI Arena is a gamified AI model discovery and recommendation platform. Instead of scrolling through spec sheets to pick an AI model, users take a short "AI Quest," get a personalized **AI DNA** priority profile, watch models compete in an **Arena**, and walk away with a transparent, explainable recommendation — backed by a **Trust Score** and a shareable **Model Passport**.

Built for **CodeFury 9.0**, under the AI Marketplace problem statement.

## 🎯 Problem

Choosing the "right" AI model is confusing and largely a popularity contest — benchmark leaderboards don't account for what *an individual user* actually values (accuracy vs. speed vs. cost vs. privacy vs. ease of use). Most comparison tools show raw numbers with no context on *why* a model fits — or doesn't fit — a specific need.

AI Arena turns that into a personalized, explainable decision: define what matters to you, let contenders compete on your terms, and get a recommendation with the evidence to back it up.

---

## ✨ Key Features

- **AI Quest** — a short, five-question flow that captures what a user is optimizing for (Accuracy, Speed, Cost, Privacy, Ease of Use).
- **AI DNA Profile** — converts Quest answers into a weighted, five-dimension priority profile visualized for the user.
- **Arena — Live Model Competition** — ranks contender models against the user's AI DNA, with a head-to-head "battle" view where two models respond to the same prompt side by side.
- **Match Score & Trust Score** — Match Score reflects fit against the user's AI DNA; Trust Score reflects confidence in the recommendation, broken down per dimension plus an evidence score.
- **"Why didn't the others win?"** — expandable, model-by-model explanations for every contender that wasn't recommended, not just the winner.
- **Model Passport** — a collectible, shareable record of the recommendation: winning model, scores, AI DNA alignment, best use cases, and why alternatives lost. Supports Download, Share, and Copy Link.
- **Deployment Config** — lets the user tune basic inference settings (temperature, max tokens, response format) and generates ready-to-use starter code in JavaScript, Python, and cURL.
- **History / My Passports** — a personal archive of past Quest profiles and saved/completed Arena results.
- **AI Chatbot ("Ask AI")** — a floating assistant available across the app to answer questions about a user's AI DNA, recommended model, and scores.
- **Light/Dark theme** — a full design system built on CSS custom properties, with the selected theme persisted for the user.

## 🧬 The AI DNA / Recommendation Concept

This is the core idea behind AI Arena:

1. **Quest → AI DNA:** The user's five Quest answers are converted into a weighted priority profile (e.g. Accuracy 35%, Privacy 22%, Ease of Use 15%, Speed 16%, Cost 12%) — their "AI DNA."
2. **Arena → Deterministic Scoring:** Each contender model is scored against the user's AI DNA using **deterministic weighted-sum scoring** — the ranking and Match Score are computed directly from the weights and model metrics, not generated by an LLM.
3. **LLM → Explanation Only:** An LLM (Groq/Llama) is used strictly to *explain* the result in natural language — why a model won, why the others didn't — never to decide the ranking itself. This keeps the recommendation transparent and reproducible.
4. **Result → Trust Score:** A separate Trust Score is computed to reflect confidence in the recommendation (per-dimension trust plus an evidence signal), distinct from the Match Score.
5. **Passport → Persistence:** The full verdict — model, scores, DNA alignment, reasoning, and alternatives — is captured as a Model Passport the user can revisit, share, or take straight into Deployment.

## 🧭 Complete User Flow

```
Home → Login / Sign Up → AI Quest → AI DNA → Arena → Result (Winner) → Model Passport → Deployment → History
```

| Step | Route | What happens |
|---|---|---|
| 1. Home | `/` | Learn the concept, see live model previews, start the Quest |
| 2. Login / Sign Up | `/login`, `/signup` | Account entry points |
| 3. AI Quest | `/quest` | Answer 5 priority questions |
| 4. AI DNA | `/dna` | View the resulting 5-dimension priority profile |
| 5. Arena | `/arena` | See ranked contenders, run a live head-to-head battle |
| 6. Result | `/result` | View the winning model, Match Score, Trust Score, and evidence |
| 7. Model Passport | `/passport`, `/passport/:id` | Save/share the collectible recommendation record |
| 8. Deployment | `/deployment` | Configure the winning model and copy generated starter code |
| 9. History | `/history` | Revisit past Quest profiles and Passports |

A persistent 6-stage journey indicator (`Quest → DNA → Arena → Result → Passport → Deploy`) tracks progress across the app.

## 🛠 Tech Stack

### Frontend
- **React** with **TypeScript**
- **Vite** as the build tool
- **React Router** for routing
- **CSS** — custom design system built on CSS custom properties, with light/dark theme support

### Backend
- **Next.js (App Router)** for API routes
- **MongoDB Atlas** as the database
- **Groq / Llama** for natural-language explanation of results (explanation only — scoring is deterministic)
- **bcryptjs** for password hashing
- **jose** for JWT-based authentication

> The scoring/ranking logic itself is a deterministic weighted-sum calculation on the backend, not an LLM decision — the LLM's role is limited to generating human-readable explanations of an already-computed result.

## 🏗 Architecture / Project Structure

The project is split into a frontend (React + Vite) and a backend (Next.js App Router) built independently and connected via a configurable API base URL.

```
frontend/
├─ src/            # Application source (pages, components, routing)
├─ dist/           # Production build output
├─ package.json
└─ vite.config.*    # Vite configuration
```

Frontend routing covers the full journey listed above (`/`, `/login`, `/signup`, `/quest`, `/dna`, `/arena`, `/result`, `/passport`, `/passport/:id`, `/deployment`, `/history`), plus a global navigation bar and journey stepper shared across pages.

The backend exposes REST-style API routes under `/api/*` (see below) that the frontend calls using an environment-configured base URL, so no backend URLs are hardcoded into page markup.

---

## 🔌 API / Backend

Backend endpoints exposed via Next.js API routes:

| Endpoint | Purpose |
|---|---|
| `/api/auth/*` | Authentication (sign up, login, session) |
| `GET /api/models` | List available contender models |
| `POST /api/quest/submit` | Submit Quest answers, receive the AI DNA profile |
| `POST /api/arena/rank` | Get ranked contenders / Match Scores for a given AI DNA |
| `POST /api/arena/test` | Run a live head-to-head battle between two models |
| `POST /api/result/trust-score` | Compute the Trust Score for a result |
| `POST /api/result/explain` | Generate the "why it won" explanation |
| `POST /api/result/why-not` | Generate "why didn't the others win" explanations |
| `GET /api/quest/history` | Fetch a user's past Quest profiles |
| `GET /api/results` | Fetch a user's saved results |
| `GET /api/results/:id` | Fetch a single result / Passport by ID |
| `GET /api/health` | Health check |

**Current integration status:** the frontend calls these endpoints when `VITE_API_BASE_URL` is configured. Without it, the app falls back to fixed demo data so the full flow can still be demoed end-to-end. Login/Sign Up screens exist in the UI but are not yet wired to the auth endpoints.

## ⚙️ Setup & Installation

### Prerequisites
- Node.js (LTS recommended)
- A package manager: npm, yarn, or pnpm
- Access to the backend's MongoDB Atlas instance and a Groq API key (for full functionality)

### Clone the repository
```bash
git clone <repository-url>
cd ai-arena
```

### Install dependencies
```bash
# frontend
cd frontend
npm install

# backend
cd ../backend
npm install
```

---

## 🔐 Environment Variables

**Frontend** (`frontend/.env`):
```env
VITE_API_BASE_URL=<your backend URL, e.g. http://localhost:3000>
```

**Backend** (`backend/.env`) — confirm exact variable names with the backend maintainer before use:
```env
DATABASE_URL=<MongoDB Atlas connection string>
JWT_SECRET=<secret used by jose for signing tokens>
GROQ_API_KEY=<Groq API key for the Llama explanation model>
```

---

## ▶️ Running Locally

```bash
# start the backend
cd backend
npm run dev

# in a separate terminal, start the frontend
cd frontend
npm run dev
```

Open the frontend at the local URL shown in your terminal (Vite's default is `http://localhost:5173`) with `VITE_API_BASE_URL` pointing at your running backend. Without a backend running, the app still functions using demo data for every stage of the flow.
